## Finding

- `src/gaia_cli/steward/prmaintenance/executor.py:346` — **warning: final source/content proof can be redirected through local Git replacement objects.** The executor rechecks eligibility through `gate.validateWrite`, which uses `prmaintenance/proofs.py:36-48` to read commit content with ordinary Git. Those subprocesses honor local `refs/replace/*` and `GIT_REPLACE_REF_BASE`; neither the production boundary's existing environment checks nor those reads disable or reject replacement objects. Consequently the immutable full head SHA sent to GitHub can identify a different actual commit from the content that was evaluated. A pre-existing or introduced local replacement ref can cause a tampered rendered report at that exact real head to be evaluated as the contents of a clean commit. Final post-claim reauthorization repeats the same substituted reads, so it does not repair the discrepancy.

  **Fresh reproduction:** `.gaia/whole-review-probes/test_replace_object_boundary.py` constructs a disposable real Git content fixture and the concrete `ProductionServices`/coordinator seam with fixture transport, clock, snapshots and independent-verifier inputs. Before adding a replacement ref, the actual tampered head is refused as `not-eligible: routine_pr_founder_decision: rendered surface is not proven to be an instance of the base template`. The probe then creates a local replacement mapping from that exact bad commit to a clean fixture commit, without changing the requested bad SHA or its API-shaped file list, and prepares/executes the operation. Result: `merged`, **1 invocation / 1 effect** at the fake forge. Both the initial gate and final adapter recheck saw the substituted Git content. This tests a fixture-only sender and does not claim an actual GitHub write, a bypass of GitHub's external protections, or that an untrusted remote can itself create local replacement refs. It shows a failure of the assigned Git/object-override defense if the checkout's local replacement refs or relevant Git environment are not trusted as authorization inputs.

  **Repair:** ensure every Git object/history read used to establish source authority, payload/scope eligibility and coordination history ignores or fails closed on replacement refs and object interpretation overrides, including local refs and inherited replacement-ref configuration. Prefer explicit `git --no-replace-objects`/a sanitized, enforced subprocess environment at the common boundary; validate interaction with local Git configuration and all relevant readers rather than fixing just this test. Add adversarial fixture regressions for both local replacement refs and environment-selected replacement namespaces, verifying the real head is rejected before mutation and that invocation/effect counts remain zero.
