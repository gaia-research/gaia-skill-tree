## Finding

- `src/gaia_cli/steward/archive.py:243-269` — **critical**: The unbundled-artifact eligibility guard is not fail-closed for ordinary relative paths. It recognizes selected key substrings and file extensions, but not `receipt` or `evidence` keys, relative paths with other extensions, or extensionless relative paths. In a disposable bare Git remote, use a settled synthetic `run_record` with `phases={"observe":{"receipt":"receipts/proof.bin","evidence":"evidence/build-output","payload":"x" * 10000}}`. `phase_hold(phases)` returns `None`, `plan` returns `run-a` eligible, and `migrate` archives it, leaving hot `phases` empty. `show` returns the strings, not the referred bytes. No artifact was opened or bundled. This contradicts the promised refusal for phase file references and permits phase evidence to leave hot state without portable bytes; the JSON snapshot itself is not evidence-byte preservation. Repair using a conservative schema-aware allowlist for known safe phase fields, explicitly holding unknown/reference-bearing fields and all non-portable path shapes, or safely bundle and verify bounded actual bytes. Add relative, extensionless and arbitrary-extension regression cases, including unknown key shapes. Do not simply broaden a filename-extension list and claim fail-closed behavior.
