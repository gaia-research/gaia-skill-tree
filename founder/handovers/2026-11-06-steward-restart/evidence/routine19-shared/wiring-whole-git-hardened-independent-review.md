## Finding

- `src/gaia_cli/steward/prmaintenance/proofs.py:44-48` and `:259-260` — **warning: inherited Git attributes can hide real base history from the final content proof.** `safeGitEnv` retains `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_*` / `GIT_CONFIG_VALUE_*`, and `exportBase` uses `git archive`, which honors `core.attributesFile` and `export-ignore`. A caller-controlled or ambient Git attributes configuration can therefore omit an existing base report from the exported history. `contentEngineProofs` rebuilds the archive from that incomplete export and can accept a PR that silently drops the report from both indexes. The hardened `--no-replace-objects` flag does not affect archive attributes. `ProductionServices` can be constructed with this environment and its post-claim `gate.validateWrite` repeats the same incomplete proof.

  **Fresh fixture reproduction:** `.gaia/whole-review-probes/test_attrs_omits_history.py` uses an actual disposable Git content repository, concrete production service/coordinator, fixture current authority/clock and fake forge. The PR head keeps the old report files but removes report `2026-42` from both generated indexes. With no override the real gate refused: `index-rebuild: index.json rows differ from the rebuild ...; index.html differs from the rebuild`. The probe then sets, only in its pytest process, `GIT_CONFIG_COUNT=1` with `core.attributesFile` naming a fixture attribute file containing `/docs/reports/2026-42/index.html export-ignore`; it constructs a new `ProductionServices` while the environment is present. The same bad head is prepared and executed: **`merged`, 1 invocation / 1 effect** on the fake forge. No GitHub or real namespace was touched. The independent verifier is a fixture PASS; this demonstrates that the separately required deterministic content gate can be bypassed, not that real GitHub protections or a genuine independent reviewer necessarily fail. A separate low-level probe independently confirmed the environment-selected attribute file removes a real base file from `exportBase`.

  **Repair:** establish the base-history proof from exact tree/blob entries without untrusted archive attribute filtering, or explicitly neutralize and verify all attribute sources including environment, global/repository configuration, local `info/attributes`, and base-tree attributes while ensuring required tree entries are not omitted. Merely excluding `GIT_CONFIG_COUNT` does not cover repository or local attribute files. Add negative tests for each supported attribute source and a clean-head positive control, asserting no adapter invocation/effect for an omitted historical report. Preserve the no-replace and graft defenses.
